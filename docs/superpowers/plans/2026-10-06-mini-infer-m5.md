# mini-infer M5: Paged KV Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Retain the user's existing native execution method and one final independent reviewer.

**Goal:** Add a shared page-pool cache, safe FIFO page-pressure admission, and honest fixed-budget capacity/fragmentation measurements while preserving contiguous inference.

**Architecture:** Each paged request reserves its full capacity as fixed-size blocks before admission. Logical-token indexing gathers one layer at a time into the existing attention or scheduler workspace; explicit release returns blocks on completion. The scheduler retains M4 phase recovery, and the contiguous implementation remains the default and correctness reference.

**Tech Stack:** Python 3.11.17, PyTorch 2.5.1, transformers 4.48.3 for loading/tests only, pytest 8.3.5; standard library for allocation metadata and CSV. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-06-mini-infer-m5-design.md` (approved).

## Global Constraints

- Standalone `harshith49/mini-infer` only; branch `codex/mini-infer-m5`, M4 base `f16da70ee54b444c2af1d449830abe3a5bbdc01e`; current design commit `d4f54a0`. No merge or force push.
- Default pages hold 16 tokens; reserve `ceil((prompt_length + max_new_tokens) / page_size)` pages for positive-budget requests. Waiting requests hold no pages; zero-output requests need none.
- Reject requests larger than the entire pool before submission mutation. Queue behind the first waiter that cannot fit; old running requests continue. Full reservation prevents growth-related deadlock.
- Preserve all original M1–M4 tests/tolerances, model arithmetic, contiguous default, sampling streams, and M4's documented additional public suffix-check scope. HF never executes inside engine inference.

- Pool resident memory persists after completion. Separate actual storage, live reservations, committed bytes, rounding waste, unused logical capacity, and gather buffers; CPU process peak is unmeasured.

## Review Focus

1. Reused nonconsecutive pages contain stale/NaN tails; only newly written real prefixes may affect logits — Task 2 poisons returned pages and exercises cross-page gathers.
2. The second staged reservation or prefill forward fails after earlier reservations succeed; all staged IDs must return without changing waiting/RNG state — Task 3 injects each failure separately.
3. Admission is blocked by a larger head waiter despite a later small request fitting; continuing requests finish and FIFO order remains intact — Task 3 pins a literal page-pressure trace.
4. Completion reports no live requests while resident pool tensors still occupy memory; counters must include pool and simultaneous gathers once — Tasks 2/3 test exact byte formulas.
5. Fragmentation results could imply real allocator measurements or a global packing optimum; CSV must identify metadata-only scope and maximum admitted FIFO prefix under the supplied capacities — Task 4 validates scope fields, trace replay and equal effective budgets.

## Task 2: Logical paged cache and direct-model parity

**Files:** Extend `engine/kv_cache.py`, `engine/model.py`, `tests/test_paged_cache.py`; add direct paged acceptance in `tests/test_correctness_vs_hf.py`.

**Interfaces consumed:** Task 1 pool constructor/allocation/release/properties.

**Interfaces produced:** Both `SimpleKVCache` and `PagedKVCache` expose `read_prefix(layer_idx: int, *, length: int | None = None) -> tuple[Tensor, Tensor]`, defaulting to committed length, and `store(layer_idx: int, offset: int, key: Tensor, value: Tensor) -> None` without advancing length. Explicit read length may include the tentative suffix written by `write`, but cannot exceed logical capacity. Existing `write` stores at committed length and returns the prefix ending at the new chunk. Simple reads are views; paged reads allocate only `[1, heads, length, head_dim]` K/V. `PagedKVCache(pool: PagePool, *, capacity: int)` has `config`, `capacity`, `length`, `requires_attention_mask`, immutable `page_ids`, `validate(...)`, `write(...)`, `allocated_bytes`, `used_bytes`, `rounding_bytes`, `unused_bytes`, and idempotent `close()`. Counters for a closed cache are zero, its ID tuple is empty, and forward/read/store/write reject. `close` resets committed length/mask metadata.

## Task 4: Fixed-budget measurements, docs and publication

**Files:** Create `benchmarks/bench_paged.py`, `tests/test_paged_benchmarks.py`, `results/paged_cache.csv`; update README, architecture, lessons and this plan. No M2/M4 CSV edits.

**Interfaces produced:** `run_capacity_experiment(config, *, capacities: list[int], budget_bytes: int, page_size: int, device, dtype) -> list[dict[str, object]]`; `run_fragmentation_experiment(config, *, budget_bytes: int, page_size: int, device, dtype) -> list[dict[str, object]]`. Each returns contiguous/paged rows. Use actual bytes per model token; derive `num_pages = budget_bytes // page_bytes` and identical effective budget `num_pages * page_bytes`. Fragmentation requires at least four pages and `2 * page_size <= config.max_positions`. Validate before allocating. Clean capacity is the maximum FIFO prefix of the supplied reservations, not arbitrary bin packing.

**Experiment defaults:** FP32, page size 16, requested budget 32 MiB, capacities `[17] * 32`. Clean contiguous allocates real Simple caches until the next cannot fit; paged allocates real tables from one fixed pool. Neither writes model K/V, so committed used bytes are zero; this is reservation-capacity measurement. In fragmentation, fill every page-sized interval/table, free even-indexed reservations, then probe capacity `2 * page_size`. The contiguous comparator is standard-library first-fit interval metadata with coalescing on free; paged uses real nonconsecutive pool IDs. Close all remaining paged tables in `finally`.

**CSV fields:** `stage`, `experiment`, `allocation_kind`, `device`, `hardware`, `torch_version`, `dtype`, `page_size`, `requested_budget_bytes`, `effective_budget_bytes`, `budget_remainder_bytes`, `request_capacities`, `allocation_trace`, `live_requests`, `probe_admitted`, `resident_bytes`, `reserved_bytes`, `used_bytes`, `rounding_bytes`, `unused_logical_bytes`, `free_slots_before_probe`, `largest_free_run_before_probe`, `free_slots_after_probe`, `largest_free_run_after_probe`, `peak_memory_bytes`, `peak_memory_kind`. JSON lists/traces; LF endings. Stages `contiguous`/`paged`, experiments `clean_capacity`/`fragmentation_trace`. Allocation kinds `real_contiguous_tensors`, `real_page_pool`, `metadata_first_fit_arena`. Metadata-arena resident bytes and process peak are blank/unmeasured; reserved bytes there are explicitly logical arena capacity. No throughput/latency column for this allocation-only experiment.
