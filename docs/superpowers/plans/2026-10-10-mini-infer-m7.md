# M7 streaming HTTP generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve concurrent GPT-2 generations as SSE, release request state reliably, and publish actual client throughput and latency.

**Architecture:** One background thread loads and exclusively owns the existing model, tokenizer and Scheduler. FastAPI lifespan and handlers communicate with it through standard-library commands and asyncio notifications; native StreamingResponse emits bounded per-request event queues. HTTPX drives real network checks and the load test.

**Tech Stack:** Python 3.11.17, existing PyTorch 2.5.1/transformers 4.48.3/pytest 8.3.5/safetensors 0.8.0. Add FastAPI 0.143.0, Uvicorn 0.54.0 and HTTPX 0.28.1; pin their schema/streaming dependencies Starlette 1.7.0 and Pydantic 2.14.0. Official PyPI metadata checked October 10: these versions permit Python 3.11, FastAPI permits Starlette >=0.46.0 and Pydantic >=2.9.0. Runtime compatibility is verified after approval, not claimed from metadata alone.

**Spec:** `docs/superpowers/specs/2026-10-10-mini-infer-m7-design.md`, approved by the user.

## Global Constraints

- Standalone `harshith49/mini-infer`, branch `codex/mini-infer-m7`, M6 base `bbbf070366eaa7ff2760dfe26f58bbab01968642`. Retain native execution in this checkout and one fresh independent final review. Draft PR targets M6 while unmerged; no parent-repository mutation or merging.
- Defaults: bind `127.0.0.1`, port 8000, one process, device auto, max batch size 2, maximum outstanding streams 64, contiguous KV and FP32 weights. Paged defaults remain 32 pages of 16 tokens. Prompt at most 65,536 characters; GPT-2 context 1,024 tokens.
- Endpoint `/v1/generate`, budget 50, temperature 0, top_k 0, top_p 1, seed 0, EOS stop default; explicit empty stop list disables stopping. Strict schema, unknown fields forbidden, finite numeric values, no Boolean/string coercion. Preserve original prompt text, seed empty tokenization with EOS.
- Before SSE headers: invalid requests 422, capacity exhausted 429, worker unavailable 503. After headers: `token`, `done` or terminal `error` SSE as specified. Generated stop IDs count in usage even when invisible in text.
- One worker owns every model/tokenizer/Scheduler operation. Cancellation happens between forwards. Retain stream slots until stream closure and acknowledged worker disposal; at most token budget plus one terminal buffered event per stream. No automatic inference retry or worker restart.
- Existing FP32 token-exact 50/logit 1e-4 and M6 centered-logit/5% perplexity gates remain unchanged. CPU evidence mandatory, CUDA conditional. No weights/secrets or downloaded sample text committed; earlier CSVs untouched.
- Default load test: 8 requests, concurrency 4, prompt `The future of machine learning is`, 32 outputs, seed 0, no EOS stop, separate single-request warmup. Client metrics include transport/parsing; server peak batch is a lifetime counter.
- No separate SSE library, broker, multiple model workers, authentication/session framework, full OpenAI compatibility or M8 packaging.

## Review Focus

1. Cancellation while admission is awaiting acknowledgment must not strand a submitted request or release capacity prematurely — Task 2 tests the handshake under a blocked forward.
2. A fatal worker fault racing with new admission must wake every waiter and reject later requests — Tasks 2/3 test command-queue draining and fail-closed HTTP behavior.
3. Rapid disconnects and slow consumers must not produce unbounded pending callbacks/commands despite nominal queue limits — Tasks 2/3 test slot retention, event invalidation and full finite buffers.
4. Literal replacement characters and malformed GPT-2 byte sequences must not corrupt previously streamed Unicode — Task 2 tests actual public tokenizer decoding plus a prefix-violation fixture.
5. A truncated or duplicated SSE terminal response must fail the load test rather than inflate throughput — Task 4 tests malformed streams and complete denominator accounting.
