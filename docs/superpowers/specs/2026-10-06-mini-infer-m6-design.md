# mini-infer M6: transparent int8 weight-only quantization

## Goal and approved approach

Implement per-output-channel symmetric int8 storage for GPT-2 transformer linear weights, with dequantize-on-the-fly floating matmul. Learning value and honest measurements take priority over speed. The user approved the proposed approach on October 6, 2026. Preserve the original FP32 engine and all original correctness gates; quantized greedy output may differ and receives separate error/quality acceptance.

M6 starts at M5 commit `7dd066be28c1a7c2622f7f10b11fb385fbc92c4b` in the standalone `harshith49/mini-infer` repository. Work on `codex/mini-infer-m6`; publish a draft PR against M5 while that dependency remains unmerged. Preserve earlier CSVs and draft PRs. Retain native execution with one fresh independent final review. This spec requires written review, followed by a written implementation plan, before product implementation.

## Scope and alternatives

Use a small custom `Int8Linear` in `engine/quantize.py` and PyTorch's existing floating linear operation. Quantize each block's attention QKV/output and MLP up/down projections: 48 linear layers in GPT-2 small. Biases, embeddings, normalization parameters and the tied vocabulary projection remain FP32. This intentionally preserves the shared embedding/head parameter and means whole-model savings are smaller than fourfold. Document this exclusion wherever the stage is described.

Native CPU dynamic quantization is an alternative but changes the transparent algorithm and is not the requested portable CPU/CUDA reference. Custom integer/CUDA kernels add complexity without serving the current learning goal. No new dependency, calibration framework, activation quantization, kernel, architecture, server or quantized checkpoint format is needed.

## Quantization and conversion contract

For a linear weight matrix `[out_features, in_features]`, each output row has its own positive FP32 scale. Normally `scale = max(abs(row)) / 127`; all-zero rows use scale one. Quantized values are `round(weight / scale)` clamped to `[-127,127]` and stored as `torch.int8`. PyTorch's round-to-nearest-even behavior is part of the reference. Protect nonzero subnormal rows with a smallest-normal-FP32 scale floor to prevent a zero denominator; zero rows still reconstruct exactly. Compute conversion intermediates with sufficient precision to avoid overflow in otherwise finite FP32 inputs. Reject nonfinite source weights/biases or a nonfinite reconstructed matrix before attaching the replacement.

`Int8Linear.from_linear(...)` accepts an ordinary FP32 `nn.Linear` with finite weights/bias, on available CPU or CUDA. Store only int8 weights, one FP32 scale per output row, and optional FP32 bias as inference buffers. Preserve input/output dimensions, bias presence, device and evaluation state. Do not retain the source module or floating weight tensor. Input must be floating FP32 on the same device with the correct final dimension; arbitrary leading dimensions work as with Linear. The inference forward reconstructs the current layer's floating matrix and calls `torch.nn.functional.linear`, then releases reconstruction with normal local lifetime. No permanent dequantized cache hides the memory/time tradeoff. Conversion and forwarding are inference-only; differentiable training and `.to(dtype=...)` mixed precision are outside the contract. Moving the model between supported CPU/CUDA devices preserves int8 and FP32 buffer dtypes.

`quantize_model(model)` converts only a custom `GPT2Model`, in place, returning it for convenient programmatic use. Validate all target modules and source values before replacing any layer; incompatible/mixed already-quantized topology rejects clearly without partial validation-driven mutation. Calling it again on a fully converted compatible model is idempotent. Tensor allocation failure during conversion is not an atomic resource-recovery guarantee; load a fresh FP32 model if that happens. Conversion is performed with exclusive ownership, never during an active request.

Weight mapping stays unchanged: load/map the public checkpoint into FP32 first, release the HF reference, convert transformer projections on CPU if selected, then move the result to the requested device. No engine forward invokes HF. Add `EngineConfig.int8: bool = False`, validated as a Boolean; add `--int8` to single, fixed-batch and scheduler CLIs, forwarding the flag through their shared loader. Default behavior and output formats remain unchanged. Programmatic generation/batching/scheduling need no new flags because they operate on the supplied model. Contiguous/paged KV state stays FP32, deriving device/dtype from the unchanged embedding.

## Correctness gates

Original M1–M5 public FP32 logit/token tests run unchanged after M6. Quantization must not mutate the shared FP32 reference fixture. Compare a separately converted custom model with an unmodified custom FP32 model loaded from the same weights.

Tiny tests establish exact int8/scale values for asymmetric sign patterns, per-row ranges, ties, zero rows and optional bias; reconstructed weight error is bounded by half a quantization step plus floating rounding. Cover finite extremes/subnormals, rejection of invalid/nonfinite/device/dtype inputs, repeated conversion, preserved tied embedding/head identity, removal of original projection storage, actual buffers/state, and no previous reconstruction retained before the next layer. Check multidimensional inputs against independently reconstructed weights, not another invocation of the same helper.

Quantized models must work through uncached, contiguous cached, static masked and paged scheduler execution, including cross-page offsets and retry of a model-forward fault. Compare cached/uncached logits at the existing FP32 tolerance where the same quantized arithmetic permits it; compare exact tiny-model generated outputs against independent generation on that same quantized model. Public quantized cached/paged 50-token outputs are compared with quantized independent generation, not required to equal FP32/HF tokens. Retain the inherited M4 long-history numerical limitation without narrowing its existing gates.

Public quantized full-forward logits on the existing three prompt fixtures, after subtracting each token's vocabulary mean from both models, must have maximum absolute error at most **2.0** and root-mean-square error at most **0.25** versus FP32. These are quantization-specific absolute-error budgets, not replacements for original 1e-4 FP32 gates. Record both raw and centered maxima/RMSE. The quality acceptance is at most **5% relative perplexity increase** on the fixed sample below (`quantized_ppl / fp32_ppl - 1 <= 0.05`). A decrease is acceptable. The original raw-logit gates failed; after diagnosis, the user approved centered-logit checks on October 7, 2026, with the same numeric bounds. The independent quantization formula reproduced the outputs exactly, and most raw error was an additive vocabulary offset that cancels in softmax. This amended gate permits those offsets while retaining raw-error reporting; original FP32 gates and the 5% perplexity gate remain unchanged. Conditional CUDA tests check conversion/device movement and same-device execution/parity/error budgets; no cross-device token identity or CUDA result is claimed without hardware.

## Reproducible public sample and perplexity

Use the upstream Tiny Shakespeare `input.txt` rather than a dataset framework. The original request permits a small public text sample, with WikiText-2 as an example. Download with standard-library HTTP at runtime into ignored `model_cache/quality/`, never commit the text. Immutable source URL:

`https://raw.githubusercontent.com/karpathy/char-rnn/370cbcd448eb7daf32f21a6be560b70e0b33c4e3/data/tinyshakespeare/input.txt`

The URL was actually fetched during design exploration: 1,115,394 bytes, valid UTF-8, SHA256 `86c4e6aa9db7c042ec79f339dcb96d42b0075e16b8fc2e86bf0ca57e2dc565ed`. Validate checksum on cache reads and downloads, use a finite timeout and bounded response size, and atomically replace a complete validated temporary file. A corrupt cache fails clearly instead of silently evaluating different text. Honor `HF_HUB_OFFLINE=1`: verified local data is reused; missing data fails with a download instruction. Downloads need no key.

Tokenize the entire verified UTF-8 file once using the same public GPT-2 tokenizer, without adding special tokens, then select the first **4,097 tokens**. Score exactly **4,096 next-token targets**, indices 1 through 4,096, using both models and the same IDs. Default context is 1,024 and target stride is 512. For each successive target block `[a,b)`, forward token slice `[max(0,b-context), b)` and sum shifted cross-entropy only for global target indices `[a,b)`. Every target has a preceding token; score each once. The first block has shorter context; later windows retain up to 1,023 preceding tokens. Validate enough tokens, context/stride bounds and model vocabulary/device before computation. General test-local context/stride values are allowed to prove indexing without loading GPT-2.

Accumulate summed NLL in FP64, divide by the actual scored count, and exponentiate once for perplexity. Do not average per-window perplexities or score overlap twice. Release full vocabulary logits after each window. Use inference/eval mode, no KV cache and no EOS stop for quality evaluation. Report token count, context, stride, token-ID/sample checksums, source URL/revision, both average NLLs and perplexities and relative delta. This is a small deterministic smoke-quality sample, not full WikiText perplexity or broad model-quality evidence. Public quality acceptance is mandatory; lack of network/cache is a failure with actionable context, not a skipped test.

## Memory and speed measurement

Add `benchmarks/bench_quantization.py` and `results/quantization.csv`. Measure a fresh FP32 model first, then convert that same owned model in place after releasing stage-local tensors. Measure int8 under identical settings. Do not retain a second model during timing or CUDA memory measurement. Tiny/public correctness tests can use separate models outside measurement.

Reuse the existing cached single-request workload timing helper: deterministic seed-zero synthetic prompt IDs of lengths `[16,64,128,256]`, 32 output tokens, no EOS stopping, one warmup, three repetitions, one CPU thread by default. A quantized model's own warmup/result must remain deterministic; cross-stage token equality is not a gate because quantization can change argmax. Require the same prompt IDs/counts and output budget in both stages. Label FP32 cached and int8-transformer-weight cached stages explicitly. Loading, conversion, tokenizer and quality evaluation stay outside timed generation. Keep the existing per-token instrumentation/CUDA synchronization scope and report median tokens/sec, TTFT, decode p50/p95 and the measured throughput ratio, including slowdowns.

Report weight storage bytes separately from total resident model tensor bytes. Deduplicate shared underlying storages so the tied embedding/head is counted once. Weight storage includes floating parameters and quantized weight/scale/bias buffers; total model storage additionally includes causal masks/other model buffers. Report actual byte counts and whole-model weight reduction, not a theoretical fourfold claim. KV reservation remains unchanged; peak CPU process memory is unmeasured. CUDA peak, if run, is PyTorch allocated tensors including the single resident model, KV/logits and temporary layer reconstruction; it is not driver/process memory. Record maximum one-layer FP32 reconstruction bytes separately as an analytic tensor-size bound, not measured process peak. Conversion peak is unmeasured unless explicitly measured separately.

CSV rows carry device/hardware, torch version, thread count, model config, quantization scope/formula, prompt/output/repetition counts, timings, weight/model/KV byte scopes, unmeasured cells and quality provenance/results. Attach the same fixed-sample quality metrics to each workload pair. Run the actual CPU benchmark isolated from tests; prior M2/M4/M5 CSVs remain unchanged. CLI rejects invalid positive lengths, repetitions, thread count and quality-window settings before costly work when possible. Default command: `python -m benchmarks.bench_quantization --device cpu`.
